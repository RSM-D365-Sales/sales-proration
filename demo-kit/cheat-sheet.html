Before you walk up

  • Start the demo build from the repo root (PowerShell). It serves the Bluestem snapshot and makes no D365 calls. 
    $env:D365_SNAPSHOT_FILE = 'demo-kit/data/bluestem-snapshot.json'
$env:OUTBOX_FILE = 'demo-kit/data/outbox.jsonl'
$env:PORT = '5199'; node server/index.js
  • Open the Planning overview. Blueberries should read Short 67.4%, Overall fill 110.5%, "2 need attention", and the blueberry ship dates should be one to eight days out. If the dates look old, run node demo-kit/seed.mjs and refresh; it re-anchors every date to today with the same numbers.
  • Browser at 100% zoom, window at least 1280 px wide so the ribbon holds all four nav items.
  • Know the cast below. Every customer, order and figure is Bluestem's fictional demo set. Never describe it as a live tenant or as executed ERP postings.
Don't press Approve & Send on the hosted site: it posts a real message to the DEV08 proration queue. On the demo build it only appends a row to the local outbox (you will see it under Batches), which is fine for the conversation. Don't open Setup → Test active connection; it is a developer page and its result confuses the story. Refresh, filters, Prorate, Re-run, the allocation inputs and the Sub… picker are all safe.

The story in thirty seconds

A wet week took a bite out of the Michigan blueberry harvest. Bluestem has 4,390 cases of open blueberry demand against 2,960 available, and twelve customers who all want their full order. Rosa used to settle that on the phone, one buyer at a time. Now the planning overview flags Blueberries red, she opens it, prorates every item with one click, chooses the policy (equal cut for everyone, or protect the strategic accounts), nudges a line where she knows better, offers a substitute from the same buyer group, and sends the whole batch back to Dynamics 365 as one message. The order lines update in D365 in batch, with an audit trail and an idempotent batch id.

Questions you will get

Is this actually talking to D365?

Yes, by design. The app reads one custom-service operation, SPASalesOrderService.GetOpenSalesOrders, which returns the whole planning snapshot (demand, supply, items, commodities, customer priorities) in one call under an Entra client-credentials token. Approve posts one SysMessageService.SendMessage carrying the batch. The booth build reads a file in the same shape so the show floor doesn't depend on the DEV08 sandbox or its Contoso data.

Where does the priority come from?

A one-to-five proration priority on the customer master (a CustTable extension). Weighted scales each request by its weight, solves for the factor that spends exactly the available quantity, caps any line at its request and re-solves, then hands out rounding remainders one case at a time to the lines with the most unmet demand. Whole cases only, and the total always equals supply.

What is History-Aware?

The weighted strategy with a debt factor: customers shorted in recent weeks float upward (alpha 0.5, four-week lookback). The feed doesn't send fill-rate history yet, so it runs as Weighted and the app says so rather than pretending.

How do substitutions work?

A short line can be offered another item from the same buyer group that still has inventory in its pool. D365's substitution whitelist (RSMItemSubstitution rules) ranks the candidates and applies a quantity ratio; a candidate without a rule is badged "unverified" and D365 would reject it. Substitutions travel as their own message type on the same queue.

What happens inside D365?

The message processor consumes the batch, updates the sales line quantities in batch, writes an audit record per line, and uses the batch id as the idempotency key, so a redelivered message is a no-op.

Can we prorate by site or warehouse?

The proration call already takes site and warehouse filters; the screen prorates per item across sites today. Site-level buttons are a small UI change.

How is it hosted?

Static front end on Cloudflare Pages behind a custom domain, an Azure Functions API that holds the D365 secret and validates Entra tokens, single-tenant Entra sign-in with app roles (Proration.Admin, Proration.User). Everything is white-label: the whole look comes from one branding file.

If something goes wrong

  • "Couldn't load data from D365" with a Retry button. The demo server isn't running, or it was started without the two environment variables. Start it with the three lines above and press Retry.
  • Figures differ from this sheet, or dates are old. Run node demo-kit/seed.mjs from the repo root and refresh. It is seeded, so the same numbers come back with today's dates.
  • Someone pressed Approve & Send on the demo build. A new row appears under Batches and nothing left the machine. Re-run the seed to put the outbox back to two rows.
  • The hosted site shows Contoso customers and speakers. Expected: it reads the DEV08 sandbox. Use the demo build for the booth, or ask the D365 team to load the Bluestem set into a legal entity.
  • Nothing loads at all. Fall back to the looping reel while you restart the server.
